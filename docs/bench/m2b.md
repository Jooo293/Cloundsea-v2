# M2b 基线记录：多 pass 重构（半分辨率云 + bloom）

> 目标：把最贵的云层降到半分辨率，并补上真正的 bloom 链，为 M3 之后的功能腾出帧预算。
> 日期：2026-11-17

## 1. 渲染结构（7 个 pass）

| # | pass | 分辨率 | 内容 |
| --- | --- | --- | --- |
| 1 | `sky.frag` | 云倍率（默认 0.75） | 渐变夜空 + 星点 + 背景 12 层云 |
| 2 | `fg.frag` | 同上 | 前景 2 层云（输出平均色 + alpha） |
| 3 | `composite.frag` | 全分辨率 | 上采样云图 + 城市 + 列车 + 烟 + 桥 + 前景云 + 粒子 |
| 4 | `bright.frag` | 1/4 | 高光提取（阈值由主题给） |
| 5 | `blur.frag` | 1/4 | 横向 5 抽头高斯 |
| 6 | `blur.frag` | 1/4 | 纵向 5 抽头高斯 |
| 7 | `final.frag` | 全分辨率 | 场景 + bloom + 暗角 |

关键点：**只有云层（含前景云）降分辨率**，列车/桥/城市/粒子保持全分辨率，所以边缘不糊。主题 `bloom=0` 时跳过 4–6 步。

画质档位映射到云倍率：`流畅 0.5 / 标准 0.75 / 高清 1.0`，也可用 `?cloudscale=` 覆盖。

## 2. 踩到的坑：`iChannel0` 被两套语义复用

第一版把 `sky` 的输出直接喂给 `composite` 的 `iChannel0`，但 `common.glsl` 里 `latticeSample()` 一直用 `iChannel0` 采样噪声图。结果 composite 里的烟噪声读到了**云图**，烟从"细碎的蒸汽"变成一团光滑的香蕉形光斑（截图对比可复现）。

修法：噪声单独占 `uNoise`（纹理单元 3），`iChannel0/1` 只做"场景输入"。这是多 pass 重构最容易踩的坑，记在这里避免复发。

## 3. 性能（1080p，Intel Arc 核显，60 帧 / `readPixels` 同步）

| 云倍率 | cyber（含 bloom） | classic（无 bloom） | 说明 |
| --- | --- | --- | --- |
| 0.5 | **4.24 / 4.65 ms** | 4.00 / 4.88 ms | 像素量 1/4，云边缘明显变软 |
| **0.75（默认）** | **8.73 / 8.88 ms** | 6.40 ms | 边缘锐度接近原始，余量约 7.8 ms |
| 1.0 | 12.2 ms | — | 与原 M2 持平 |

对比 M2（单 pass，1080p）：classic 12.09 ms、cyber 9.47 ms。默认档 0.75 下 cyber 从 9.5 → 8.9 ms，且**多了 bloom**；若接受 0.5 的柔化，可到 4.2–4.6 ms。

> 0.5 与 0.75 的边缘差异可以直接看图对比：云带边缘在 0.5 下会糊成 2–3 px，0.75 接近原始的硬边水彩感。因此默认选 0.75。

## 4. 回归验证

多 pass + 全分辨率云（`?cloudscale=1&theme=classic`）与原版同帧对比：

| 指标 | 结果 |
| --- | --- |
| 平均绝对误差 | 0.68 / 255 |
| 差异 > 8 的像素 | 0.88%（全是 1px 抗锯齿描边） |
| 3×3 实心差异块 | **0 个像素** |

结论：拆 pass、改采样路径后，classic 在全分辨率下仍与原版等价；默认 0.75 是有意的画质取舍，不是回归。

## 5. bloom 参数

| 主题 | 强度 | 阈值 |
| --- | --- | --- |
| classic | 0（跳过整条链） | — |
| cyber | 0.95 | 0.55 |
| ink | 0（水墨不该发光） | — |
| polar | 0.40 | 0.62 |
