# M0 基线记录

> 目标：把原版删成"只有云海"的干净工程，并证明**画面与原版一致（除诗句）**、记下改造前的性能天花板。
> 日期：2026-11-17

## 1. 验证方式：与原版像素级对比

为了排除"看起来差不多"的主观判断，做了 A/B 对照：

1. 给原版 `index.html` 打一个最小补丁（仅用于对照，不进入工程）：`start().then(() => { elapsed = 12.5; rate = 0; poetryEnabled = false; })`，让原版在 **t=12.5s、关闭诗句** 下渲染一帧；
2. 新工程用 `?freeze=1&t=12.5` 渲染同一时刻；
3. 取两块 UI 都不覆盖的区域（x 420–1150，y 140–760）做逐像素差分。

| 指标 | 结果 |
| --- | --- |
| 平均绝对误差 | **0.056 / 255** |
| 最大通道误差 | **5 / 255** |
| 差异 > 2 的像素占比 | **1.33%**（集中在云边缘的亚像素抗锯齿） |
| 差异 > 8 的像素占比 | **0%** |

结论：**去掉诗句没有改变云海、列车、烟、桥、前景云的任何一处画面**，误差来自两次渲染的采样相位，不是逻辑改动。

对照图：`shots/m0.png`（新工程）vs `shots/ref-t12.5.png`（原版，t=12.5、诗句关）。

## 2. 帧时基线

### 环境

| 项 | 值 |
| --- | --- |
| 浏览器 | headless Edge（`--headless=new`） |
| 图形后端 | ANGLE / Direct3D 11 |
| GPU | Intel Arc Graphics (0x7D55)，核显 |
| 测量方式 | 启动后连续渲染 40 帧，每帧 `gl.readPixels(1×1)` 强制同步，取平均 |
| 预热 | 3 帧不计入 |
| 时间轴 | 固定步进 `i/60`，与 rAF / vsync 无关 |

> `gl.finish()` 在部分后端会直接返回，量不到 GPU 时间；改用 1 像素回读才拿到真实数据（对比：`finish` 版报 0.01 ms，回读版 5–21 ms）。

### 结果（同一台机器，`?bench=40&w=&h=`）

| 渲染分辨率 | 平均帧时 | 折算上限 | 余量（60 fps 预算 16.6 ms） |
| --- | --- | --- | --- |
| 1280×720 | **8.09 ms** | ~123 fps | 8.5 ms |
| 1600×900 | **10.26 ms** | ~97 fps | 6.3 ms |
| 1920×1080 | **14.23 ms** | ~70 fps | 2.4 ms |
| 2560×1440 | **20.86 ms** | ~48 fps | **−4.3 ms（已超预算）** |

复现命令：

```powershell
python -m http.server 8789 --bind 127.0.0.1          # 工程根目录
python tools/bench-server.py                          # 另开一个：收 bench 结果
# 浏览器打开：
# http://127.0.0.1:8789/index.html?bench=40&w=1920&h=1080&report=1
# 结果追加到 shots/bench.jsonl
```

## 3. 这组数字说明了什么（对后续里程碑的约束）

1. **1080p 只剩 2.4 ms 余量**，1440p 已经超预算。原版是"一帧跑 14 层 8 octave fbm"，本来就吃满了核显。
2. 所以 M2（粒子 + bloom）、M5（域扭曲 + 位移）、M6（天气）**不能直接叠加**，必须先把云 pass 降到半分辨率——这是计划里"降级阶梯"的第 1 条，现在有了数据支撑：半分辨率约省 3/4 像素成本，预计 1080p 能回到 ~6 ms。
3. 独立显卡上这组数字会宽松很多；但**必须按核显设计**，否则移动端和轻薄本直接不可玩。
4. 每加一个特性，都要用同一命令复测并写进 `docs/bench/`，超预算不入。

## 4. 本里程碑删掉/保留了什么

### 删除（对照原版）

| 内容 | 影响 |
| --- | --- |
| `poetryRecords`（18,587 条，1.93 MB） | 单文件瘦身 9% |
| `createPoetryRenderer` + `iPoetry` 纹理 + 每帧 `texImage2D` | 每帧少一次全画布纹理上传与一次 2D canvas 绘制 |
| `#verse-hit-layer` / `syncVerseTargets` | 不再需要每帧同步几十个透明按钮 |
| 工作台 / 成诗浮层 / 情绪分析（约 330 行 DOM 逻辑） | 交互重心让位给列车 |
| 星云、极光场景 + 切换按钮 | 只留云海 |
| `CloudPoetry.ttf`（3.9 MB） | 不再需要内联字体 |
| 死代码（`loadText`、`resizeCanvas`、`showRenderError`、`reloadOnContextRestore`、`productionTrainCombinedMask`） | 可读性 |

### 保留（行为与原版一致）

`common.glsl`（噪声/fbm/列车 mask/烟/桥/暗角）、`scene.glsl` 的 14 层云与叠加顺序、`post.glsl` 暗角、两趟渲染结构、时间轴语义（暂停/倍速/重置）。
