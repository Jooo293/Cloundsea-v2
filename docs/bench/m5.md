# M5 基线记录：液态云 + 列车拨云

> 目标：让云层从"横向平移的色带"变成会翻卷的流体；列车穿过时把云排开。
> 日期：2026-11-17

## 1. 三个机制

| 机制 | 做法 | 成本 |
| --- | --- | --- |
| 域扭曲 `uWarp` | **整屏算一次**低频流场（2 次 4-octave fbm），把这个偏移加到所有云层的采样位置上 | 2 次 fbm / 像素，不随层数增长 |
| 浪尖 `uRidge` | `n = mix(n, 1 - abs(2n-1), ridge)`，把圆钝的 fbm 压出尖峰 | 一条 `mix` |
| 列车拨云 `uCarve*` | 椭圆核（`vec2(0.55, 2.2)` 各向异性）下压云高 + 环状隆起，背景云与前景云都生效 | 每层几个 `step/exp` |

域扭曲特意**没有**写进每层循环里：如果每层各算一次流场，12 层就要 24 次 fbm，帧时会直接翻倍。现在的做法是所有层共享同一个扭曲偏移，视觉上依然整体流动。

## 2. 主题参数

| 主题 | warp | ridge | carve |
| --- | --- | --- | --- |
| classic（回归基线） | 0 | 0 | 0 |
| cyber | 0.12 | 0.15 | 0.10 |
| ink | 0.18 | 0.30 | 0.08 |
| polar | 0.10 | 0.12 | 0.09 |

`?carve=N` 可把拨云强度整体放大 N 倍，用于调试（默认 1）。

## 3. 回归验证

| 指标 | 结果 |
| --- | --- |
| classic 改动前后 | **平均差 0.0000，最大差 0** |

warp=0 时 `warpOffset` 是零向量、ridge=0 时 `mix` 恒等、carve=0 时整段被跳过，所以经典画面逐像素不变。

## 4. 性能

| 主题 | M4 | M5 | 增量 |
| --- | --- | --- | --- |
| cyber | 8.88 ms | **10.14 ms** | +1.3 ms（2 次 fbm 流场 + 逐层 carve） |
| ink | 8.94 ms | 7.45 ms | 噪声（测量波动） |

1080p 仍有余量约 6.5 ms。

## 5. 诚实说明：静态列车下"拨云"不明显

现在列车是静止的，所以 carve 只是一个固定的凹陷。我把强度放大到 4 倍做过验证：**约 2.3 万像素发生变化**（包围盒 x 0–628、y 496–712，正好是列车与前景云带的位置），但 1 倍强度下肉眼几乎看不出——因为凹陷只是把云层降了一档色带，而不是露出天空。

它真正会好看是在 **M7 列车飞行**：列车移动时 carve 跟着走，才会出现"船过水面"的尾迹。M5 把机制和参数通道都留好了：

```js
renderer.setCarve(x, y, radius);   // 云空间 uv，M7 每帧跟着列车更新
```

## 6. 验收结论

- [x] 域扭曲 / 浪尖 / 拨云三个通道就位，主题可独立开关
- [x] 域扭曲只算一次流场，成本可控（+1.3 ms）
- [x] classic 像素级不变（最大差 0）
- [x] 拨云位置可通过 `setCarve()` 外部驱动，供 M7 使用
- [ ] 拨云的观感要等列车能动之后才算真正验收
- [ ] M6：动态天气（晴 / 阴 / 雷暴 + 闪电）
