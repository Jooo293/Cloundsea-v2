# 部署上线（GitHub + Vercel）

项目是纯静态站点：`index.html` + `src/` + `assets/`，没有构建步骤、没有 npm 依赖。
Vercel 当成静态托管即可，`vercel.json` 已经配好缓存头与 `cleanUrls`。

---

## 0. 先说清楚当前网络状况

这台机器**直连 GitHub 会失败**（`Recv failure: Connection was reset`），但系统代理是通的：

- Windows 系统代理：`127.0.0.1:7897`（浏览器走它，所以 github.com 网页能打开）；
- `git` 默认不走系统代理，所以 `git push` 会重置。

给仓库单独配上代理即可（不动全局配置）：

```powershell
cd cloudsea-v2
git config http.proxy http://127.0.0.1:7897
git config https.proxy http://127.0.0.1:7897
```

> 代理端口以你实际使用的为准（Clash 常见 7890 / 7897，v2rayN 常见 10809）。
> 换网络后如果 push 又失败，先 `git config --get http.proxy` 确认。

## 方案 A：Vercel CLI 直接部署（最快，不依赖 GitHub）

适合先上线看效果，之后再接 GitHub。

```powershell
cd cloudsea-v2
npx vercel login        # 浏览器里登录（GitHub / 邮箱都行）
npx vercel              # 首次会问项目名、目录，全部回车用默认
npx vercel --prod       # 发布到生产域名
```

- 首次 `npx vercel` 会问 `Set up and deploy?` → 回车；`Which scope` → 选你的账号；
  `Link to existing project?` → `N`；`Project name` → 回车（默认 `cloudsea-v2`）；
  `Directory` → 回车（当前目录）。
- 发布成功会打印形如 `https://cloudsea-v2-xxxx.vercel.app` 的地址。
- `.vercelignore` 会把截图 / 文档 / 工具排除，上传只有几 MB。

**以后更新**：改完代码再跑一次 `npx vercel --prod`。

## 方案 B：GitHub → Vercel（推荐长期）

### B1. 在 GitHub 建空仓库

网页操作：<https://github.com/new> → 名字例如 `cloudsea-v2` → **不要**勾选 README / .gitignore / license
（本地已经有提交，勾了反而要合并）→ Create repository。

### B2. 关联并推送

```powershell
cd cloudsea-v2
git config http.proxy http://127.0.0.1:7897
git config https.proxy http://127.0.0.1:7897

git remote add origin https://github.com/<你的用户名>/cloudsea-v2.git
git branch -M main
git push -u origin main
```

首次 push 会要求登录：Windows 一般弹 Git Credential Manager 窗口，选 **Sign in with your browser**，
浏览器里授权一次即可（之后会记住）。如果命令行里卡住不动，先 `git config --global credential.helper manager`。

> 已经 push 过、后来又改了 remote？`git remote set-url origin <新地址>`。

### B3. 在 Vercel 导入仓库

1. <https://vercel.com/new> → 选 `Import Git Repository` → 授权 GitHub → 选中 `cloudsea-v2`；
2. 配置页：
   - **Framework Preset**：`Other`
   - **Build Command**：留空（不要填 `npm run build`）
   - **Output Directory**：留空（根目录就是站点）
   - **Install Command**：留空
3. `Deploy` → 一两分钟出地址 `https://cloudsea-v2.vercel.app`。

之后每次 `git push` 到 `main`，Vercel 自动重新部署；PR 还会生成预览地址。

## 4. 常见问题

**Q：浏览器控制台报 `加载 src/shaders/sky.frag 失败（404）`？**
检查文件是否真的推上去了（`git ls-files src/shaders`），以及大小写——Vercel 跑在 Linux 上，**大小写敏感**，
Windows 本地不区分，所以 `Sky.frag` 本地能跑、线上 404。

**Q：`favicon.ico` 404？**
无害，只是没放图标。想消掉就加一个 `favicon.ico` 到根目录。

**Q：页面一片空白？**
先看控制台。常见原因是单文件构建把模块拼进同一作用域后顶层重名 —— 但线上跑的是 `index.html`（模块版），
不受影响；如果你部署的是 `dist/cloudsea.html`，那要按单文件的规则检查。

**Q：想同时提供"单文件版"下载/预览？**
`dist/cloudsea.html` 现在被 `.gitignore` 排除。要发布它就把它纳入版本控制（删掉 `.gitignore` 里的 `dist/`），
提交后访问 `https://<你的域名>/dist/cloudsea.html`；或者单独建一个 Vercel 项目指向 `dist/`。

**Q：`npx vercel` 下载慢或失败？**
npm registry 是通的（已测 200）；如果卡住，换 `npm config set registry https://registry.npmmirror.com` 后重试。
