> 前置：已完成对原版《云海拾句》的源码拆解（见 `../../up-in-the-cloud-sea/docs/复现文档.md`）。
> 本计划基于"保留云海场景、去掉诗词与另外两个场景"的前提，把项目从「诗歌阅读装置」改造为「可操控的云海世界」。

## 1. 目标与非目标

### 1.1 目标（可验收）

1. **只剩云海**：星云、极光两个场景及其切换按钮移除；诗句相关内容 100% 清除。
2. **三套主题可切换**：赛博朋克霓虹 / 国风水墨 / 极地冰雪，切换无白屏、无重载，配置纯数据。
3. **云层能"变形"**：从"水平云带"升级为可配置的液态流动；列车穿过时云被拨开。
4. **天气可切换**：晴天 / 阴天 / 雷暴，带过渡与闪电。
5. **列车可操控**：点击蓄力 → 脱轨 → 云海自由飞行 → 回轨。
6. **可进车厢**：切到乘客视角，看到内饰、窗外云海、像素乘客。

### 1.2 非目标（本版不做）

- 不做 3D 场景/自由相机（保持侧视 2.5D 构图，这是原版的辨识度所在）；
- 不做关卡、任务、评分系统；
- 不做服务端、账号、分享链接（本地 localStorage 即可）；
- 不做诗词/文本内容（明确删除）。

> **需要正视的取舍**：去掉诗句后，作品从"有内容"变成"有氛围"。建议用「环境叙事」补足：站牌、路牌、广播字幕、旅途日志（可选，见 M9），否则用户打开后只有 3 分钟新鲜感。

### 1.3 用户旅程（决定交互取舍）

```text
打开（默认主题 + 晴天） → 3 秒内看到云海与列车在跑
  ↓ 指针横移
视差：城市/远山随指针轻微偏移，云层按距离差速
  ↓ 点「主题」/「天气」
皮肤与天气在 300 ms / 6 s 内切换
  ↓ 长按列车
蓄力 1.2 s → 脱轨 → 云被拨开 → 自由飞行
  ↓ 靠近轨道 / 10 s 无操作
自动回轨，提示"已回到轨道"
  ↓ 点车窗
进入车厢：内饰、窗外云海、像素乘客
```

整条链路的目标是 **30 秒内让用户动起来、3 分钟内看到三种主题**。凡是挡住这两件事的功能，都往后排。

## 3. 技术架构

### 3.1 工程结构

```text
cloudsea-v2/
├─ index.html                 # 只留 <canvas id="gl"> + HUD 骨架
├─ src/
│  ├─ main.ts                 # 装配：engine + scene + ui + 状态机
│  ├─ engine/
│  │  ├─ gl.ts                # context、program 缓存、uniform 反射
│  │  ├─ fbo.ts               # 多级 FBO（场景纹理 / bloom 链）
│  │  ├─ pass.ts              # 全屏三角形 + drawPass
│  │  ├─ clock.ts             # elapsed / 暂停 / 倍速 / 冻结（截图用）
│  │  └─ input.ts             # 指针/键盘/触摸 → 意图（intent）
│  ├─ scene/
│  │  ├─ clouds.ts            # CloudField：层参数 + 域扭曲 + 位移
│  │  ├─ train.ts             # 列车状态机、物理、遮罩采样
│  │  ├─ sky.ts               # 天空渐变、天气云量
│  │  ├─ elements.ts          # 城市剪影 / 远山 / 仙鹤 / 极光
│  │  └─ post.ts              # bloom、扫描线、闪白、纸纹
│  ├─ themes/
│  │  ├─ theme.ts             # Theme 类型与校验
│  │  ├─ cyber.ts  ink.ts  polar.ts
│  │  └─ weather.ts           # sunny / overcast / storm 预设
│  ├─ views/
│  │  ├─ rail.ts  flying.ts  passenger.ts
│  │  └─ hud.ts               # 主题/天气切换、蓄力条、提示
│  └─ shaders/
│     ├─ cloud.vert / cloud.frag
│     └─ post.frag
├─ tools/
│  ├─ shot.mjs                # 无头截图（golden image 测试）
│  └─ build-singlefile.mjs    # 内联成单文件发布包
└─ docs/  （本计划 + 每里程碑的 bench 记录）
```

### 3.2 渲染图（每帧）

```text
[1] 天空 pass      → FBO_A（半分辨率可选）  天空渐变 + 天气云量 + 极光 + 星点
[2] 远景元素 pass  → FBO_A                  远山 / 城市剪影 / 极光帘幕（在云之后）
[3] 云海 pass      → FBO_A                  12~14 层云（数据化）+ 域扭曲 + 列车位移
[4] 列车 pass      → FBO_A                  列车几何 + 烟 + 桥（按主题材质）
[5] 近景元素 pass  → FBO_A                  仙鹤 / 近处霓虹招牌 / 飞雪（在云之前）
[6] bloom 链       → FBO_B..D               降采样 + 模糊 + 叠加（仅发光主题开）
[7] 合成 pass      → 屏幕                    暗角 + 扫描线 + 闪白 + 纸纹 + 调色 LUT
```

与原版的关键差别：

- **不再有 `iPoetry` 纹理**，帧内少一次 2D canvas 绘制 + 一次全画布 `texImage2D`（这是原版最贵的一次上传）；
- 元素按景深拆成"云前/云后"两组 pass，远山与城市被云遮住、仙鹤与飞雪浮在云上——原版是靠一个 fragment 里的叠加顺序硬凑的，拆开后更好维护；
- 所有 pass 共用一套 `uTime / uResolution / uWeather / uTheme`，避免参数爆炸。

> 备选：M5 之后云层计算量上升，可把 [1][2][3] 收到一张半分辨率 FBO，再在 [7] 里升采样——云的边缘本来就柔，几乎看不出差别，性能约省 4 倍像素。

### 3.3 Theme 配置（纯数据）

```ts
export type Theme = {
  id: 'cyber' | 'ink' | 'polar' | 'classic';
  sky: { top: RGB; horizon: RGB; bottom: RGB; stars: number };
  cloud: {
    bands: RGB[];          // 按层深取样（原版是每层 3~4 个硬编码 vec3）
    saturation: number;    // 0..1
    contrast: number;      // 0.5..2
    warp: number;          // 域扭曲强度（液态云）
    edgeStyle: 'crisp' | 'ink' | 'crystal';
    layerCount: number;    // 8..14
  };
  train: {
    body: RGB; trim: RGB; emissive: RGB;
    material: 'metal' | 'wood' | 'ice';
    snow: number;          // 0..1 积雪覆盖
    lights: number;        // 0..1 灯带亮度
  };
  elements: { city: boolean; mountains: boolean; cranes: boolean; aurora: boolean };
  post: { bloom: number; scanline: number; grain: number; paper: number };
};
```

所有主题共用**同一个 shader**，差异全部通过 uniform 与 4 个正交开关表达：

| 开关 | 影响 | 实现 |
| --- | --- | --- |
| `edgeStyle` | 云边缘处理 | `crisp`=硬边；`ink`=fwidth 边缘积墨；`crystal`=Voronoi 高光 |
| `material` | 列车材质 | 金属渐变 / 木纹噪声 / 冰面反光 |
| `elements.*` | 背景层 | 各自独立绘制函数，主题只决定开关 |
| `post.*` | 后处理强度 | 统一后处理链，强度为 0 即关闭 |

这样**加主题不改 shader**，只在 `themes/` 里加一个对象——这是三套皮肤能在 5–6 人日内落地的根本原因。

### 3.4 状态机

```text
        press & hold
rail ───────────────→ charging ──release──→ flying
 ↑                                            │
 └──────── 靠近轨道 / 10s 无输入 ───────────────┘

rail | flying ──按 C / 点车窗──→ passenger ──ESC──→ 回到上一状态

任意状态：T 切主题（1→2→3），W 切天气（晴→阴→雷暴），Space 暂停，F 全屏
```

视图与渲染是**解耦**的：`passenger` 视图只是换一套 DOM/Canvas 覆盖层，云海 FBO 继续在后台跑（窗口 portal 直接用这张纹理）。

### 3.5 Shader 变体

云 shader 会随功能膨胀（液态 + 天气 + 位移 + 三种边缘）。**不要用运行期 `if` 堆分支**，用 `#define` 预编译 3–4 个变体：

| 变体 | 启用 | 用途 |
| --- | --- | --- |
| `VARIANT_BASE` | 域扭曲 + 层参数 | 水墨 / 极地 |
| `VARIANT_WARP` | + 强域扭曲 + ridged 噪声 | 液态 |
| `VARIANT_STORM` | + 乌云压暗 + 闪电 | 雷暴 |
| `VARIANT_CARVE` | + 列车位移 | 飞行 / 穿云 |

切换变体时重新 link（几十毫秒），在天气/模式切换的过渡期做，用户无感。

## 4. 三套主题的实现方案

### 4.1 赛博朋克霓虹云海（M2，垂直切片）

**视觉拆解**

| 层 | 目标 | 技术手段 |
| --- | --- | --- |
| 天空 | 深紫→品红→青的渐变，带星点与微弱扫描线 | 3 色 LUT 按 `uv.y` 插值；星点复用极光的 `hash21` |
| 云 | 紫/蓝/粉分层，云底暗、云顶亮，边缘微发光 | 层色带按深度取样 + `pow(h, 0.8)` 提亮 + bloom 溢出 |
| 粒子 | 上升的数据流/尘埃，近大远小 | GPU 点精灵（单 buffer，属性=seed/速度/尺寸），additive |
| 城市 | 3 层视差剪影，带窗光与霓虹招牌 | 程序化天际线（每层一组矩形 SDF）+ 噪声窗格 + 色块发光 |
| 列车 | 银灰金属 + 霓虹灯带 + 车头光锥 | 材质渐变 + `emissive` mask（车厢下沿一条带）+ 径向光晕 |
| 后处理 | bloom + 轻微色差 + 扫描线 + 暗角 | 3 级降采样高斯 + `chromatic aberration` 采样偏移 |

**关键实现**

```glsl
// 云层配色改为按深度取样，而不是每层写死 vec3
vec3 bandColor(float depth) {                 // depth: 0 远景 → 1 近景
  return texture(uPalette, vec2(depth, 0.5)).rgb;
}
// 灯带：复用列车 mask，只取车厢下沿区域（车体真实区间是 y∈[0.103,0.115]）
float neon = step(0.103, uv.y) * step(uv.y, 0.110) * step(uv.x, 0.45);
col += uTrainEmissive * neon * 3.2;           // 交给 bloom 去炸
```

**验收**

- 四层（天空/云/城市/列车）在任何窗口比例下都可辨；
- 粒子 15k–20k，1080p 下帧预算内；
- 主题切换 < 300 ms，无白屏；
- 与参考图（美术定的 moodboard）并排比对，色相分布一致。

### 4.2 国风水墨云海（M3）

**视觉拆解**

| 层 | 目标 | 技术手段 |
| --- | --- | --- |
| 调色 | 去饱和，灰度 + 淡青 | `mix(gray, tint, 0.15)`；饱和度降到 0.15 |
| 云 | 边缘"积墨"、内部留白、宣纸颗粒 | `fwidth(h)` 提取边缘 → 加深；阈值 + 噪声做"飞白" |
| 纸 | 宣纸纤维与晕染底纹 | 程序化纤维噪声（拉伸的高频噪声）+ 轻微暗角 |
| 列车 | 木质复古车厢 + 铜饰 + 老式烟囱 | 新增 mask（锅炉/驾驶室/烟囱），木纹用拉伸噪声 |
| 背景 | 远山三层 + 仙鹤 | 山脊 = `abs(fbm)` 多尺度叠加；仙鹤为剪影 sprite + 振翅 |
| 后处理 | 纸纹、轻微模糊、留白边 | 只开 `paper` 与 `grain`，关 bloom |

**关键实现（水墨边缘）**

```glsl
float edge = fwidth(cloudHeight) * uEdgeGain;     // 云高场梯度 = 笔触边缘
float ink  = smoothstep(0.15, 0.55, edge);        // 边缘积墨
float dry  = step(0.42, fbm(uv * 90.0, 3));       // 飞白：随机剔除
col = mix(col, uInkColor, ink * dry * uInkAmount);
```

> 想更像"水墨"，可在 [3] 之后加一趟 **9-tap 方向性模糊**（沿高度场梯度方向），把边缘"洇"出去——成本约 1 ms，但观感提升明显。

**验收**

- 全画面最高饱和度 < 0.25（用脚本对截图取 HSV 统计）；
- 仙鹤出现频率可调（30–90 s 一只），飞行轨迹有起伏；
- 1080p / 1440p 下云雾层次不糊成一团。

### 4.3 极地冰雪云海（M4）

**视觉拆解**

| 层 | 目标 | 技术手段 |
| --- | --- | --- |
| 调色 | 冷白 + 淡蓝 + 冰面反光 | 与水墨同一后处理，饱和度低但保留蓝相 |
| 云 | 冰晶纹理、边缘反光 | `Voronoi` 边缘加亮 + `fresnel` 式高光 + 稀疏闪点 |
| 列车 | 顶部积雪、冰凌、车灯冷光 | 位移后的 mask 顶部加白 + 噪声扰动边缘；冰凌为下垂小三角 |
| 背景 | 极光 + 冰原远山 | 复用原版 `aurora()`（见 §11 许可）；远山用低饱和蓝白 |
| 天气默认 | 阴天/小雪 | 默认 `overcast`，可切晴/雷暴 |

**关键实现（积雪）**

```glsl
float snowLine = trainTop(uv) + 0.004 * fbm(uv * 60.0, 4);  // 抖动的积雪上沿
float snow = step(uv.y, snowLine) * insideTrain(uv) * uSnowCover;
col = mix(col, vec3(0.93, 0.96, 1.0), snow);
```

**验收**

- 极光可独立开关，强度 0–1；
- 列车移动时积雪不"穿帮"（跟着 mask 走）；
- 冷色调下仍然能看清车厢轮廓（对比度自查）。

## 5. 云层形态创新

### 5.1 液态云层（M5）

原版云高场只有"横向平移 + fbm"：

```glsl
h = (fbm(uv2, 8) - 0.5) * disp;   // uv2 = uv + vec2(t/dist, 0)
```

改造三步：

1. **域扭曲（domain warp）**：先算一个低频速度场，再把采样点推过去，得到"翻卷"感；
2. **各向异性**：横向压缩、纵向拉伸，云就有了"液面"的流向；
3. **ridged 噪声**：`1 - abs(fbm)` 产生尖峰，局部可做浪尖/岩浆。

```glsl
vec2 flow(vec2 p, float t) {
  float a = fbm(p * 0.55 + vec2(t * 0.06, t * 0.02), 4);
  float b = fbm(p * 0.85 - vec2(t * 0.03, 0.0), 4);
  return p + vec2(a, b) * uWarp;                 // uWarp: 0 静态 → 0.35 汹涌
}
float n = fbm(flow(uv2, t), 8);
n = mix(n, 1.0 - abs(n * 2.0 - 1.0), uRidge);    // ridged：把圆钝的噪声压出尖峰
float h = (n - 0.5) * disp;
```

**参数档位**（建议做成滑条或主题预设）：`uWarp` 0 / 0.12 / 0.25 / 0.35 对应 平静/微风/流动/岩浆。

### 5.2 列车"拨开"云层

两种方案，按投入选：

| 方案 | 做法 | 成本 | 效果 |
| --- | --- | --- | --- |
| **A. 解析位移**（推荐先做） | 在云高场里减掉一个以列车为圆心的平滑核 | 极低（几条指令） | 干净的"破口"+ 尾迹 |
| B. 反馈扰动场 | 用一张 FBO 累积"压力"，列车每帧往里面写 | 中（多一张纹理 + ping-pong） | 有惯性、会回弹的流体感 |

方案 A 的关键是**不要**只减高度，那样像被擦掉；要同时加一圈"隆起"才有被排开的感觉：

```glsl
float d = length((uv - uTrainPos) * vec2(1.0, 2.4));     // 椭圆核
float carve = smoothstep(uCarveR, 0.0, d);
float rim   = exp(-pow((d - uCarveR) * 18.0, 2.0));      // 环状隆起
h -= carve * uCarveDepth;
h += rim   * uCarveDepth * 0.35;
```

再叠一层随时间衰减的尾迹（`uv.x < uTrainPos.x` 区间内的低幅扰动），就是"船过水面"。

**验收**：列车静止/穿云/高速三态截图对比；位移场边缘无锯齿；帧耗时增加 < 15%。

### 5.3 动态天气（M6）

天气是**一组参数的命名集合**，不是新场景：

| 参数 | 晴天 | 阴天 | 雷暴 |
| --- | --- | --- | --- |
| 云层数 | 12 | 14 | 14（更厚） |
| `disp` 位移 | 1.0× | 1.4× | 2.0× |
| 亮度 | 1.0 | 0.75 | 0.45 |
| 对比度 | 1.0 | 0.9 | 1.35 |
| 饱和 | 主题值 | 主题值 ×0.8 | 主题值 ×0.7 |
| 风速（横向） | 1.0× | 1.6× | 2.6× |
| 雨/雪粒子 | 0 | 0.3 | 1.0 |
| 闪电 | 0 | 0 | 2–6 /min |

- **过渡**：所有参数在 6–10 s 内用 `smoothstep` 插值，避免跳变；过渡期间预热下一个 shader 变体。
- **闪电**：时间轴上随机触发（泊松），分三段——前导闪（微弱预闪）、主闪（全屏曝光 + 云层内亮）、余辉；形状用程序化分叉线（几次递归的随机折线）或一张预生成的闪电 LUT 纹理。
- **雷声**：程序化低频噪声 + 低通，延迟 0.3–1.2 s，音量大但短。

**验收**：三态互切 20 次无卡顿/无变体泄漏；闪电有 ≥3 种形态且不重复；`主题 × 天气 = 9` 组合全部可跑（脚本遍历截图）。

## 6. 列车交互

### 6.1 可操控与飞行（M7）

**输入设计**

| 操作 | 行为 |
| --- | --- |
| 长按列车（或画面下方蓄力按钮） | 蓄力，车头亮起、烟囱喷汽、屏幕轻微震动，进度条 0→1（1.2 s） |
| 松开 | 按蓄力值给初速与仰角，脱轨腾空 |
| 飞行中拖动 / WASD | 指针牵引（弹簧跟随）或速度增量，二者取一 |
| 靠近轨道 | 自动吸附回轨（提示"已回到轨道"） |
| 10 s 无输入 | 自动回轨，避免"卡在天上" |

**物理**（轻量，够用即可）

```ts
// 固定步长 1/120s，避免不同刷新率下手感不一致
v += accel * dt;
v *= Math.pow(0.92, dt * 60);        // 阻尼
pos += v * dt;
angle = lerp(angle, clamp(v.y * 0.4, -0.5, 0.5), 0.15);
```

**关键是"不破坏构图"**：相机不动，列车始终被约束在画面内（`clamp` 到 `[-0.1, aspect+0.1] × [0.05, 0.9]`），否则用户会把主角飞出屏幕，体验崩掉。

**验收**：蓄力→起飞→穿云→回轨全流程 ≤ 30 s 可复现；脱轨时桥/铁轨淡出 40%；列车不出画；手机端单指也能玩。

### 6.2 乘客视角（M8）

**结构**：一张 2D 内饰（程序化绘制或 SVG），中间是窗——窗内不是另一套渲染，而是**采样云海 FBO**，并按列车位移做轻微视差。这样"窗外云海"和主视图天然一致，不用同步两套逻辑。

```text
DOM 层：车内框架（窗框、座椅、行李架、灯、乘客 sprite）
Canvas 层：窗户区域 → 采样 sceneFBO（uv 偏移 = 列车位移 × 0.15 + 呼吸漂移）
Canvas 层：像素乘客（3–5 个，8–12 帧循环动画）
```

- **像素乘客**：每人一张 sprite sheet（`32×32`），状态机 = 坐/看书/打盹/挥手，随机切换；点击乘客有反应（挥手/抬头）。
- **交互**：车内也能切主题/天气（快捷按钮），进/出用 400 ms 的遮罩+缩放过渡。
- **移动端**：竖屏时车内改为上下分栏（窗在上、座椅在下）。

**验收**：进出 < 500 ms；窗外内容与主视图同一时间轴（暂停一起暂停）；乘客动画 ≥3 种状态；无 JS 报错。

1. 云 pass 降到 0.5 分辨率（像素量 ÷4）；

## 12. 待你拍板的 5 件事

1. **是否保留"单文件离线"发布？** 我建议开发期模块化，发布时用 `build-singlefile.mjs` 内联成单文件（保留原版"双击即玩"的传播优势）。
2. **三个主题都做，还是先做 1 个？** 建议先赛博朋克（视觉冲击最大、最容易验证框架），水墨/极地作为后续皮肤；如果时间紧，砍到 2 个。
3. **列车操控是"点击蓄力"还是"拖拽驾驶"？** 前者更戏剧化、更像"发射"，后者更可控；我计划两个都实现，默认蓄力、设置里切换。
4. **要不要保留"桥"？** 桥是原版构图的重要锚点，但飞行时它是障碍。建议：轨道/桥保留，飞行时淡化到 40%，回轨时恢复。
5. **极地主题里的"极光"算不算违背"去掉极光背景"？** 你的要求是删掉"极光场景"，而极地主题又天然需要极光。建议：极光只作为极地主题的天空气氛层（强度可调、默认开），不恢复独立场景与切换按钮。
