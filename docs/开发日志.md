## 2026-11-17 · M10 天气重制 + 移除乘客视角

### 变更一：天气改成 晴 / 大雨 / 大雪 / 雷暴

**原方案**：晴 / 阴 / 雷暴（阴天只是压暗，没有降水，雷暴有全屏闪白）。

**新方案**：

| 天气 | 亮度 | 对比 | 饱和 | 风 | 粒子 | 其它 |
| --- | --- | --- | --- | --- | --- | --- |
| 晴 | 1.00 | 1.00 | 1.00 | 1.0× | 稀疏上升尘埃 | — |
| 大雨 | 0.78 | 1.05 | 0.82 | 1.6× | 密集雨丝，快速下落 + 侧向漂移 | 冷蓝调 |
| 大雪 | 1.06 | 0.92 | 0.55 | 0.8× | 大颗雪片，缓慢飘落 | 冷白、低饱和 |
| 雷暴 | 0.55 | 1.18 | 0.66 | **3.2×（飓风）** | 暴雨 + 强侧向漂移 | 闪电 3 次/分 |

**为此新增的渲染能力**（都走 uniform，不改结构）：

- `uWeatherParticleSpeed`：下落速度倍率（雨 3.4 / 雪 0.35 / 雷暴 4.2）；
- `uWeatherParticleDriftX`：侧向漂移，雷暴拉到 3.4，配合 3.2× 风速形成"飓风"感；
- `uWeatherParticleShape`：0 = 细长雨丝，1 = 圆形雪片（各向异性从 `(7, 2.4)` 插值到 `(1.5, 1.5)`）；
- `uWeatherParticleSize`：雪片 1.7×，雨滴 0.85×；
- `uWeatherParticleMix` + `uWeatherParticleColor`：天气可以覆盖主题自带的粒子颜色（雨=冷蓝，雪=近白）。

**验收**：四种天气在赛博霓虹下逐一截图（`shots/weather-*.png`），无控制台报错；粒子形状/速度/颜色可区分；classic + 晴仍保持原版画面。

### 变更二：移除乘客视角

**原因**：这一版的重点是"云海 + 列车 + 天气"的氛围循环；车厢场景需要大量美术投入（座椅、行李架、吊环、乘客动作），投入产出比低，且与"看云"的主体验割裂。

**移除内容**：

- `src/views/passenger.js`（整个模块）；
- `#passenger-view` DOM 与 ~120 行内饰 CSS；
- HUD「乘客视角」按钮、`?view=passenger` 参数、`ESC` 退出逻辑与主循环里的车窗贴图。

**保留**：`docs/bench/m8.md` 作为历史记录，标注"该功能已移除"，避免后来者以为还在。

**影响**：单文件构建从 9 个模块降到 8 个；每帧少一次 canvas→canvas 贴图（虽然只在车厢视角发生）。

## 2026-11-17 · M11 暴雨 / 暴雪 / 龙卷 / 闪电，水墨改名废墟

### 反馈

1. 水墨主题改名为**废墟**；
2. 雨雪天气"屏幕上没有明显的暴雨/暴雪"；
3. 雷暴没有飓风——期望是**灰色龙卷吹过来把云层吹散**；
4. 闪电只有屏幕变亮，**没有闪电形态**。

### 变更一：主题改名 水墨 → 废墟

- `id` 改为 `ruins`、显示名「废墟」，调色从灰青换成灰褐（`#3b342e → #efe6d8`），远山与仙鹤保留；
- 保留 `THEMES.ink = ruins` 别名，旧链接 `?theme=ink` 与旧 localStorage 设置不会失效。

### 变更二：降水改成屏幕空间的三层降雪/降雨

原来的粒子是 20×11 的稀疏网格，密度太低，画面上几乎看不见。改成独立的三层函数：

- `rainField`：26/40/56 三档网格，速度 9/16/23，斜切跟随风向，细长高光条纹；
- `snowField`：16/27/38 三档网格，缓慢下落 + 正弦横向摆动，大颗圆点；
- 由 `uPrecipType`（1 雨 / 2 雪）与 `uPrecipAmount` 控制，直接 `mix` 到画面上。

截图里雨已经是明显的斜雨，雪是大颗飘落的雪片。

### 变更三：龙卷（飓风）

两处配合：

1. **云层涡旋**（`sky.frag`）：以龙卷中心为轴做角度扭曲 `ang = 4.2 × exp(-r×1.9)`，并沿半径向心拉拽 `0.09 × exp(-r×2.6)`——云层会被"拧"出旋臂；
2. **灰色漏斗**（`composite.frag`）：下窄上宽的柱体 + 竖直流动条纹 + 边缘高光 + 周围压暗 34%。

龙卷中心每帧缓慢横向漂移（`0.60 ± 0.05`），雷暴时 `uTornado = 1`。

### 变更四：闪电本体

从"整屏闪白"改成"曝光 + 电弧几何"：

- `bolt()` 用**按高度分段的折线**（每段随机抖动）拼出锯齿，而不是正弦曲线——第一版用正弦，看起来像垂下来的电线；
- 三条主枝 + 三条短分叉，各自有起止高度与宽度；
- 叠两层：细亮核心 + 宽一点的冷蓝光晕，再叠全屏曝光。

`shots/weather-storm-flash.png` 是强制 `?flash=0.9` 抓的一帧。

### 验收

- [x] 大雨：斜向密集雨丝，明显覆盖画面
- [x] 大雪：大颗雪片缓慢飘落，与雨丝形状可区分
- [x] 雷暴：灰色龙卷漏斗 + 云层涡旋扭曲 + 飓风级云速
- [x] 闪电：有锯齿主枝与分叉，不再只是亮度变化
- [x] `?theme=ink` 仍可用（映射到废墟）
- [ ] 龙卷的"把云吹散"还只是涡旋扭曲，没有真正的云层缺口；下一步可以让龙卷中心附近直接挖空云层
- [ ] 雪没有积雪效果（地面/桥面积雪）

## 2026-11-18 · M12 雨丝质感（第一档）

### 反馈

大雨"廉价感"：雨线单层、等长、平行、纯白硬边，没有纵深，也不和场景交互。

### 做了什么

按"性价比优先"的顺序，只做了第 1–2 步（第三档的雾与闪电联动留到下一轮）：

1. **长短随机 + 头尾渐隐**：每条雨丝的长度取 `0.40–1.00` 个单元、位置在单元内随机，
   alpha 沿长度方向 `smoothstep(0, 0.22, along)` 渐隐，不再是等长硬条；
2. **每层不同斜率**：三层各自 `slant × (0.55 + k×0.55)`，取消"全部平行"；
3. **微弱风噪**：逐条 `sin(t×1.7 + hash×24)×0.018` 的水平扰动，阵风感；
4. **背景色采样**：雨色 = `mix(雨白, col×1.35, 0.45)`，再按背景亮度决定可见度
   `vis = rain × amount × (0.80 + 0.60×lum)`，最后叠一点亮度回馈 `rain × 0.09 × lum`。

`rainField()` 从 12 行涨到 26 行，全部在 composite pass 的屏幕空间里，没有新增 pass、没有新增纹理。

### 数据

- 1080p 帧时：晴 8.59 ms → 大雨 8.75 ms（**+0.16 ms**，预算内）；
- 雨丝密度：`alive` 阈值 0.62 → 0.42，`precipAmount` 1.0 → 1.25。

### 对比

`shots/rain-compare.png`：上半是旧版（稀疏、等长、纯白），下半是新版（长短不一、头尾渐隐、随背景染色）。

### 还没做

- **云遮蔽衰减**：需要让 `sky`/`fg` 的 alpha 输出"云覆盖率"，composite 采样后再衰减雨——这是第 4 步；
- **雨雾**：低频噪声薄雾层，第三档；
- **闪电联动**：`uFlash` 目前只传到 final，需要再传给 composite 才能提亮雨丝；
- **水花/雨簇疏密**：第三档细节。

## 2026-11-18 · M13 降水遮挡（云缝更清、雾里更淡）

### 做了什么

1. **天空 pass 输出云覆盖率**：`sky.frag` 的 alpha 从恒为 1 改成 `bg.a`（1 = 云 / 0 = 天空）。
   这是 M12 遗留的第 4 步，之前没有通道可用来做遮挡。
2. **降水按覆盖率调制**（composite）：

```glsl
float rainVis = mix(1.0, 0.55, fg.a)            // 前景雾挡掉一部分雨
              * mix(0.70, 1.0, 1.0 - cloudTexel.a);  // 云缝里更清楚
```

   雪用更弱的遮挡（0.70 / 0.80），避免雪片在雾区被抹平。
3. **复用采样**：`cloudTexel` 与 `fg` 原本就要采样，这里只多读了 `.a`，没有额外纹理请求。

### 为什么第一版调得很轻

最初用 `mix(1.0, 0.25, fg.a)`，雾区的雨几乎消失——看起来像"下半屏没下雨"。
降到 0.55 后是"雾里淡、缝隙清"的正确观感：反射到画面上是**同一场雨在不同深度上的可见度差异**，而不是半屏断了。

### 数据

- 1080p：大雨 9.32 ms、大雪 8.27 ms（对比 M12 的 8.75 / 8.59，增量在测量噪声范围内）；
- 截图对比：`shots/rain-occlusion.png`（上：全屏均匀下雨；下：雾区变淡、云缝更清）。

### 还没做

- **雨雾层**（第三档）：低频噪声薄雾，和"遮挡"是两件事——遮挡改可见度，雾改空气质感；
- **闪电提亮雨丝**：`uFlash` 仍只传到 final；
- **水花/雨簇疏密**。

## 2026-11-18 · M14 闪电照亮雨幕

### 做了什么

1. `composite.frag` 接收 `uFlash`（之前只传到 final）：
   - 雨色 `rainTint += vec3(0.90,0.95,1.0) * uFlash * 0.55`；
   - 可见度 `vis *= 1.0 + 0.55*uFlash`；
   - 雨丝自发光 `rain * 0.09 * (0.35+lum) * (1.0 + 1.6*uFlash)`；
   - 雪同理，`snowTint` 在闪电时偏冷蓝。
2. `final.frag` 的暗角跟着收缩：`mix(vignetteFactor(uv), 1.0, uFlash*0.55)`——
   闪电瞬间画面边缘不再压暗，视觉上是"整片天都亮了"。

### 效果

`shots/storm-flash-compare.png`：上=无闪电（暗、雨不明显），下=闪电 0.9（整场雨被照亮、暗角退开、主枝与分叉清晰）。

### 数据

- 1080p：雷暴 9.3 ms 量级，与 M13 持平（只是多了几个乘加）；
- `verify.ps1` 8/8 通过。

### 还没做

- **雨雾层**：低频噪声薄雾，和遮挡是两件事；
- **水花/雨簇疏密**；
- 雷暴时云层增厚（`disp` 放大或加两层云）。

## 2026-11-18 · M15 雨雾层

### 做了什么

在 `sky.frag` 里叠一层**低频薄雾**（云之后、列车之前）：

```glsl
vec2 mp = vec2(uv.x * 2.2 + t * 0.02, uv.y * 1.4 + t * 0.01);
float m = fbm(mp, 4) * 0.6 + fbm(mp * 2.7 + 11.0, 3) * 0.4;
float band = smoothstep(0.22, 0.78, m) * (0.55 + 0.45 * smoothstep(0.0, 0.9, uv.y));
vec3 mistColor = mix(col, vec3(0.72, 0.78, 0.86), 0.55);
col = mix(col, mistColor, band * uMist);
```

- 两层不同频率/速度的 fbm 缓慢横向漂移，避免"静态灰罩"；
- 越靠上越浓（贴近云顶），下方保留近景清晰度；
- 雾色从当前画面取（`mix(col, 冷灰, 0.55)`），和 M12 的雨色采样一致，不会突然出现一块异色。

天气参数：晴 0 / 大雨 0.22 / 大雪 0.35 / 雷暴 0.42（数值，走 8 秒插值）。

### 参数取舍

第一版给到 0.55（雷暴），天空平均亮度从 36.5 提到 56.0（+53%）、87.8% 像素发生变化——
雾感对了，但对比度被压平、龙卷也糊了。降到 0.42 后保留雾气又不丢结构。

### 数据

- 晴天（uMist=0）逐像素差 **0.000**，回归基线不受影响；
- 1080p：雷暴 8.84 ms、大雨 8.42 ms；
- `verify.ps1` 8/8 通过。

## 2026-11-18 · M16 龙卷：真的把云挖开 + 看得见的螺旋柱

### 反馈

「灰色龙卷不明显；龙卷没有把云吹散，只是云在扭。」

### 变更一：在云层里挖出真正的缺口

之前只有涡旋扭曲（采样被拧），云还在原处。现在在 `sky.frag` 里直接下压云高：

```glsl
carveDelta = -smoothstep(0.26, 0.0, tr) * 1.45 * uTornado     // 中心压到天空以下
           + exp(-pow((tr - 0.27) * 8.0, 2.0)) * 0.38 * uTornado; // 边缘抬一圈云墙
```

半径 0.26（比漏斗宽）、深度 1.45 —— 12 层云会一起被压穿，露出后面的天空与城市，
再配合已有的涡旋（角度 5.5、切向拉伸）形成「被吸起来再甩出去」的结构。

### 变更二：漏斗重画

- 下窄上宽：`width = 0.026 + 0.125 * pow(hgt, 1.6)`；
- 螺旋条纹：`sin(atan(px, py) * 4 + py * 30 - t * 9)`，再叠一层细密竖流线；
- 底部尘幕 + 碎屑（hash 点）；
- 颜色从 0.50 提到 **0.74 灰**、混合 0.88、叠一层自发光 —— 这就是「灰色不明显」的直接原因：
  原来漏斗颜色和暗云几乎同亮度，怎么调都糊在一起。

### 变更三：性能教训（重要）

第一版把挖空写在 12 层云的循环里，每个像素算 12 次 `smoothstep + exp + pow`：
**1080p 从 8.88 ms 涨到 11.79 ms**，直接贴近 12 ms 门禁。

挖空对所有层的偏移是同一个标量，所以提到循环外算一次、循环里只做 `h += carveDelta`：
帧时回到 **8.88 ms**。这是这个项目里最典型的一课 —— 任何「每层都算一遍」的项，先问能不能提到循环外。

### 数据

## 2026-11-18 · M18 碎屑粒子化（并修掉漏斗里的灰色网格）

### 先解释「龙卷中心为什么是灰色网格」

不是设计，是 bug，来自两处实现：

1. 碎屑写成 `step(0.86, hash21(floor(p * 46.0)))` —— 哈希按**整数格**取值，
   每个格子要么整块亮、要么整块灭，天然就是方块阵列；
2. 漏斗表面还叠了一层 `sin(p.x * 110.0 + ...)` 的高频竖纹，频率接近像素尺度，
   与上面的格子叠加后形成摩尔纹，看起来就像「灰色网格图层」。

### 改法

1. 删掉整格亮灭的 hash 碎屑；
2. 高频竖纹降到 `sin(p.x * 58.0 + p.y * 12.0 - t * 10.0)`，不再接近像素频率；
3. 新写 `tornadoDebris()`：三层网格，每颗碎屑
   - 用连续软边 `smoothstep(size, 0)` 画成圆点，而不是方块；
   - 在格内绕小圈漂移（`orbit = 0.10 + 0.22*h2 + 0.10*sin(...)`），随时间伸缩；
   - 按 `smoothstep(0.52, 0.16, 距漏斗距离)` 遮罩——碎屑只出现在漏斗附近，
     不会像雪一样铺满全屏。

### 数据

- 1080p 雷暴 **8.84 ms**（碎屑是每像素 3 次距离计算，没有进云层循环）；
- `verify.ps1` 8/8 通过；
- 对比：`shots/tornado-debris.png`（左：漏斗上有方格纹；右：软边碎屑 + 干净漏斗）。

### 还没做

- 碎屑目前不随漏斗旋转方向一致（各自随机方向），若要更真实可以统一角速度；
- 龙卷顶部与云层的「咬合」还可以更紧（现在有一个浅色的过渡带）。

## 2026-11-18 · M19 龙卷小修：顶部硬边与碎屑旋转

### 一、修掉漏斗顶部的硬切边（这条值得记）

现象：漏斗到云顶的位置有一条明显的水平硬边，再往上还出现一块白斑。

**根因是 GLSL 的未定义行为**：`smoothstep(0.62, 0.20, p.y)` —— 第一个参数大于第二个，
GLSL 规范规定 `edge0 >= edge1` 时结果未定义。不同驱动可能给出任意结果，
本机上就表现为"要么立刻截断、要么糊成一片白"。

改法是换成单调写法：

```glsl
float profile = step(-0.06, p.y) * (1.0 - smoothstep(0.30, 0.74, p.y));
```

先试过 `smoothstep(0.92, 0.58, ...)` 和加"云领"，都因为同样的未定义行为变成白斑；
最终用 `1 - smoothstep(a, b, x)`（a < b）才稳定。

**教训：`smoothstep` 的 edge0 必须小于 edge1；要做反向渐变就写 `1.0 - smoothstep(...)`。**

### 二、碎屑统一角速度

原来每颗碎屑的角速度 `t * (0.7 + h2*1.3)` 各自不同，方向感是散的。改成同一角速度、只留相位差：

```glsl
float ang = t * 1.15 + h1 * 6.2831;
float orbit = 0.12 + 0.20 * h2 + 0.08 * sin(t * 0.9 + h1 * 6.28);
```

现在整团碎屑朝同一方向绕漏斗旋转，读起来像被同一个涡旋带着走。

### 数据

- 1080p 雷暴 **8.75 ms**；
- `verify.ps1` 8/8 通过；
- 对比：`shots/tornado-seam.png`（左：顶部白斑与硬边；右：单调渐隐）。

## 2026-11-18 · M20 雨 / 闪电 / 龙卷：从"贴在画面上"改成"画进云里"

### 反馈

「雨线、闪电、龙卷风特别廉价，像 Flash 动画，没有融入 WebGL 的画风。」

### 诊断

画面本身的语言是**平涂色带 + 噪声侵蚀的硬轮廓 + 主题调色板**（云就是 12 层按高度切色的 fbm）。
三样东西都违背了这套语言，而且都是**最后叠在画面最上层**的：

| 元素 | 旧做法 | 为什么廉价 |
| --- | --- | --- |
| 雨 | composite 里画白色细线 + 天气粒子（`particleField`）再叠一层发亮的硬线 | 纯白、等宽、不分远近，像贴纸 |
| 闪电 | final pass 里 6 条**固定位置**的折线，全屏加白 | 每次都是同一个形状、同一个位置，盖在云上面，像矢量图 |
| 龙卷 | composite 里半透明灰色渐变圆柱 + 正弦条纹 | 颜色不来自主题，没有轮廓，和云不是一种材质 |

### 做了什么

**龙卷（sky.frag，`tornadoFunnel`）**

- 漏斗改成和云同一种画法：圆柱展开的 fbm 侵蚀出硬轮廓（外缘侵蚀、芯部保留），
  明暗按"光从左上来 + 螺旋条纹"量化成 **4 档色阶**，颜色直接从**当前主题的调色板**里取（`paletteTone`）——
  classic 里是暖褐色、cyber 里是蓝灰、废墟里是灰褐，不再是一根通用灰柱；
- 插在**第 2 层云之后**：最近的两层云海会盖住漏斗底部（`background()` 新增 `out int hit` 返回命中层号做深度排序）；
- 漏斗中轴向下风侧弯、缓慢蛇形；底部有一圈卷起的云裙；
- 挖空洞壁变陡（`1 - smoothstep(0.07, 0.17, r)`）、边缘半径加噪声：旧版缓坡会让 12 层云的等高线排成一圈圈同心环（"靶心"）；
- 涡旋扭曲强度 5.5 → 3.8；composite 里的灰柱和叠加云臂带删除，碎屑改成贴着漏斗下半段的**暗色**斑点（之前是发亮的白点）。

**闪电（sky.frag，`lightningBolt`）**

- 每次落雷重新掷**落点 / 形状种子 / 是否可见电弧**（30% 只是云内闪光），回闪沿用同一通道（`weather.js` 的 `bolt`）；
- 路径是 4 个倍频的分形折线（大折 + 小抖），一次求值同时得到斜率，按斜率修正距离保证斜段不变粗；主枝上粗下细，两条分叉从主枝上长出去；
- 电弧排在**第 3 层云之后**：打进云海的那一截被近处的云吞掉；
- 云的照亮从"全屏加白"改成**以落点为中心、按云块边界扭曲、量化成 4 档的滤色提亮**——亮的是云块，不是屏幕；
- final pass 删掉旧 `lightning()`，只留很弱的整体曝光 + 原有暗角收缩。

**雨（composite.frag，`rainField`）**

- 雨丝 = **背景提亮一档并偏冷**，不再是 `mix` 到一个白色：颜色永远从画面里来；
- 三层：远层密而细（~1px），近层稀而虚；每层斜率略不同；
- 疏密由沿风向斜切的低频"雨幕"噪声控制，一阵一阵扫过（之前全屏均匀）；雨幕区域空气轻微发灰；
- 雨 / 雷暴的 `particleMul` 改为 0：旧天气粒子就是那层最"Flash"的亮白硬线。

**性能：着色器变体（重要）**

把这些代码直接加进去后，**晴天也慢了 0.5–1 ms**——分支根本不走，但多出来的代码让 Intel 核显的寄存器压力上去了。
解决：`sky` 和 `composite` 各编译两份（`#define STORM` / `#define WEATHER`），渲染时按天气选：

- `sky`：雷暴/闪电时用 STORM 变体，其余用精简变体；
- `composite`：有降水或龙卷时用 WEATHER 变体。

教训：**和"提到循环外"同一类——不用的代码也要付钱，大块的天气专属逻辑应该进变体，而不是靠 `if (uniform)` 跳过。**

**顺手修的 bug**

- `?bench` 从不走 `frame()`，天气从没上传过——**之前所有 `?weather=storm&bench=…` 量的其实都是晴天**。
  现在 bench 开始前先上传一次天气与闪电；M12–M19 记录里的雷暴帧时因此偏乐观，以本条为准。
- composite / sky 里新写和改到的地方顺带清掉了 4 处 `smoothstep(edge0 > edge1)`（见 §7 坑）。

| --- | --- | --- |

## 2026-11-18 · M21 穿云演出（云海涨潮 → 第一人称冲出 → 拉回远景）

### 需求

### 时间轴（`src/systems/cloudburst.js`，约 6.4 s）

| 时间 | 阶段 | 包络 |
| --- | --- | --- |
| 0 – 1.9 s | 三层云海从脚下涨潮：近层先漫上来，远层最后涨过头顶把天空盖住 | `cover` 0→1 |
| 1.9 – 2.5 s | 全遮挡；镜头在云里**瞬切**到车头前方（看不到切换），速度线起势 | `zoom` 1→2.6、`speed` ↑ |
| 2.5 – 4.4 s | 冲出：焦点处炸开一个硬边破洞，三层云按不同速度被推向四周（视差） | `burst` 0→1 |
| 2.5 – 6.4 s | 镜头从第一人称平滑拉回第三人称远景，径向速度模糊逐渐消失 | `zoom` 2.6→1、`speed` ↓ |

触发：HUD「穿云」按钮或快捷键 `C`；演出期间按钮禁用。截图/调试：`?freeze=1&burst=2.8` 定格在第 2.8 秒（bench 同样支持）。

### 怎么做到"和原作一个画风"

迭代了 6 版，前几版的问题都值得记：

1. **半透明噪声雾**：一片糊，像 PS 滤镜——原作没有任何"半透明的云"；
2. **矩形边距驱动蔓延**：长成一圈圈相框；改椭圆衰减后又变成同心环（像暗角）；
3. **按"离前缘多深"给色**：一层细暗线，像海岸线地图；
4. **最终方案：直接复用原版云层的算法**——`fbm(uv, 8)` 当"云面高度"，云面以下按深度切硬色带
   （贴着云面最亮，往下一档档变深，和原版 `dh` 色带同一逻辑）；颜色取主题前景云的三档色
   （`theme.fg` 的最暗 / 中间 / 最亮），所以四个主题自动匹配；天气压暗时演出云跟着压暗。
5. **fbm 必须 8 个倍频**：试过降到 6 省帧时，云边立刻变成软团——增益 0.7 下最高两个倍频决定了那种细碎的颗粒边。
6. **破洞要硬边**（2px 抗锯齿）：软边破洞是一圈糊环，和硬边云格格不入。

镜头：final pass 以焦点为中心缩放采样场景（推近 = 第一人称），冲刺时沿径向 6 次采样做速度模糊 + 轻微震动；
第一人称阶段再叠一层沿径向流出的噪声（方向向量 + 对数半径，没有 `atan` 接缝）和很细的放射速度线。

### 性能（重要，第三次踩同一个坑）

演出代码直接写进 final 后，**不演出时也慢了 ~3.5 ms**（全分辨率 pass，分支不走也付寄存器压力）。

| 1080p cyber（quality=1，4 次取中位数） | 帧时 |
| --- | --- |

| 雷暴，演出中（1.2 s / 3.0 s） | 11.23 / 11.04 ms |

演出只持续 6.4 s，峰值仍在 12 ms 门禁内。

## 2026-11-18 · M23 神龙伴飞（已于 M25 删除）

长按蓄力松手、列车脱轨起飞的瞬间，神龙同步出场伴飞；伴飞若干秒后游回云层深处淡出；列车提前回轨则龙同步退场；
面板【神龙】总开关；出场时云层轻微扰动；只有"蓄力松手起飞"才触发；不干扰主题 / 天气。造型参照用户给的概念图。

### 新增文件（独立模块）

| 文件 | 作用 |
| --- | --- |
| `src/systems/dragon.js` | 状态机（hidden → entering → escort → leaving）、可配置参数 `DRAGON_CONFIG`、各主题配色 `DRAGON_COLORS`、每帧生成 16 点中线与两条腿 |
| `src/shaders/dragon.glsl` | 龙身 / 背鬃 / 尾焰 / 腿爪 / 头（鹿角、长须、后脑鬃）/ 身下云团；只编进 composite 的 DRAGON 变体 |

### 改动的已有代码（只加挂点，不动原逻辑）

| 位置 | 改了什么 |
| --- | --- |
| `src/shaders/composite.frag`「列车 / 烟 / 桥」之前 | `#ifdef DRAGON` 调一次 `drawDragon()` —— 渲染顺序：远景云 → 龙 → 列车 → 近景云 |
| `src/scene/cloudsea.js` `create()` | 读取 `dragon.glsl`；`make()` 多一个 `extra` 参数（插在 common 之后）；新增两个变体 `composite-dragon` / `composite-weather-dragon` |

| `index.html` / `src/style.css` | HUD 新增【神龙】复选框（默认开） |

### 行为

- **触发**：只认 `charging → flying` 这一次跳变。沿轨道行驶、蓄力不足取消、自动回轨、`?train=x,y` 调试飞行都不会触发；
- **伴飞**：龙头锚在车头前上方 `(+0.20, +0.25)`，弹簧跟随（`follow = 3.5`），列车往哪飞龙跟到哪；身体 S 波浪从头传到尾，龙须、背鬃、尾焰、腿持续摆动；
- **出场**：从身下的云团里升起（1.0 s），同时深度从"埋在远景云里"变到"云前"；
- **退场**：伴飞时长（默认 4 s，`?dragonTime=` 可改）到了，或列车提前离开 flying（回轨 / docking），或开关被关掉 → 沉回云团、向后上方游走、缩小、被远景云逐渐吞没并淡出（2.6 s）；列车不受影响；
- **遮挡**：龙画在远景云之后、列车与近景云之前，近景云照常盖住龙；退场时按"深度"让远景云也盖上来；
- **云层扰动**：出场瞬间复用"列车拨云"的 uniform 叠一个 1.6 s 的脉冲（深度冲高后衰减、半径外扩），云块被推开——没有新增粒子；
- **天气**：龙与身下云团的颜色跟天气亮度一起压暗；龙的状态不读写天气 / 主题。

### 造型（参照概念图）

中线 14 个关键点直接从概念图上量出（龙头为原点、单位 = 画面高度），Catmull-Rom 采样成 16 点再叠 S 波浪，
着色器对 15 段折线求最近距离——所以龙身可以任意弯折（大 S、竖起的脖子、拱背、扎进云里再从左下方露出尾巴）。
画法与原作一致：平涂色块 + 硬边；腹甲横纹、背脊暗带、火焰状背鬃（尖端提亮）、鹿角、长须、火焰尾；
身下的云团用原作云层的算法（`fbm(·, 8)` 云面 + 硬色带），颜色取主题前景云。

### 验证

- 用 CDP 驱动无头 Edge **真实长按 1.3 s 再松手**：龙在起飞瞬间出场、跟随列车、约 5 s 后沉回云里、7.5 s 时已隐藏；60 fps、无报错；
- `?dragon=0`：同样的操作，列车照常起飞，龙不出现；
- 晴 / cyber / 雷暴 / `?train=` 调试飞行四种画面与 M22 发布包逐像素差 **0**（龙不在场时 composite 与之前完全一致）；
- 帧时（1080p cyber，中位数）：龙不在场 7.69 ms；龙在场 9.38 ms；雷暴 + 龙 10.57 ms（门禁 12 ms 内）；
- `verify.ps1` 6/6；`dist/cloudsea.html` 用 `file://` 真实操作一遍通过。

### 踩坑

- **单文件构建会把所有模块拼进同一个作用域**：`dragon.js` 和 `cloudburst.js` 都有顶层 `clamp01`，
  开发模式（ES 模块）一切正常，发布包直接 `SyntaxError: Identifier 'clamp01' has already been declared`，整页不渲染。
  `verify.ps1` 只测开发页，**测不出来**。新模块的顶层名字一律加前缀；改完要用 `file://` 打开 `dist` 实测一次。
- 第一版龙是"横向正弦 + 竖直距离"的小细蛇，做不出概念图里竖起的脖子和拱背——改成中线折线 + 最近距离后才对。

## 2026-11-18 · M26 音频 P0：风 / 雨 / 蓄力 / 起飞 / 雷

### 做了什么

新增 `src/systems/audio.js`，全部程序化合成（零素材、零网络请求）：

| 音效 | 做法 | 参数 |
| --- | --- | --- |
| 环境风（常驻） | 白噪声 → 带通 → 增益；0.07 Hz LFO 摆动中心频率做阵风 | 晴 760 Hz / 雷暴 460 Hz；雷暴叠一层 140 Hz 低通 |
| 暴雨（常驻） | 白噪声 → 高通 900 → 低通 6800，随 storm 淡入 | 0.13 Hz 轻起伏避免死白噪 |
| 蓄力（常驻） | 锯齿 70 → 240 Hz + 低通 380 → 2080 Hz + 带通噪声颗粒 | 音量与 `charge` 同步上行 |
| 起飞（一次性） | 正弦 95 → 34 Hz 冲击 + 带通 2200 → 380 Hz 噪声爆 | 0.7 s，跟随蓄力强度 |
| 雷（一次性） | 低通噪声长衰减 + 44/37 Hz 隆隆 + 近雷爆裂 | 延迟 0.3–1.2 s；30% 云内闷雷（无爆裂、更长） |

接线：`master → compressor → destination`，下挂 `ambient` / `sfx` 两条总线；
所有持续音都是**常驻节点 + 参数自动化**（`setTargetAtTime`），不在每帧建节点。

交互：
- 第一次 `pointerdown` / `keydown` 才建 `AudioContext`（自动播放限制）；
- 页面隐藏时 `suspend()`，回来 `resume()`；
- HUD 新增【声音】按钮、快捷键 `M`，静音状态写进 `localStorage`；
- `?freeze=1` 与 `?bench` 不建 AudioContext，截图与帧时不受影响。

### 验证音频的教训（值得记）

无头环境验证音频试了两条路都失败：

1. 实时 `AnalyserNode` 读电平 → 恒为 0。无头浏览器没有音频设备，虚拟时间也不推进 AudioContext；
2. `--virtual-time-budget` 下 `OfflineAudioContext.startRendering()` 的 promise 来不及兑现，页面就被杀了——
   虚拟时间瞬间耗尽，而离线渲染需要真实时间。

最终方案：**用 DevTools 协议按真实秒数等待**（新增 `tools/audio-check.mjs`），
并让页面用离线渲染把 RMS 打到控制台：

```
[audio] enabled=true state=running rate=48000
[audio] offline {"rms":0.120,"peak":0.525}
RESULT: PASS（rms=0.1203576145591548）
```

同一套自检对 `dist/cloudsea.html`（`file://`）也通过，说明单文件构建没有把音频模块弄坏。
