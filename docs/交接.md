# 交接说明（给 DeepSeek / 其他 AI 编码助手）

> 目标：对方拿到交接包后，能在**不问你**的情况下跑起来、改对地方、并且知道什么不能碰。
> 当前进度：**M25**（2026-11-18）。

## 0. 交付方式

| 方式 | 适合 | 怎么做 |
| --- | --- | --- |
| **能跑命令的 Agent（推荐）**：DeepSeek 的 harness / Claude Code / Codex 等 | 反复迭代、自己跑自检 | 解压整个文件夹作为工作区；入口是根目录的 `AGENTS.md`（再指向完整手册 `CLAUDE.md`） |
| 网页对话（只能上传文件） | 只改局部、或先出方案 | 上传 `AGENTS.md` + `CLAUDE.md` + `README.md` + `docs/` + 要改的源文件；先让它给方案再贴代码 |
| API / 自动化流程 | 接流水线 | 把 `CLAUDE.md` 全文放进 system prompt，仓库挂成工具 |

无论哪种，**先让它在全新会话里读 `AGENTS.md` 和 `CLAUDE.md`**。

> 关于文件名：`CLAUDE.md` 是最初用 Claude Code 开发时的约定名，内容对任何助手通用。
> 如果你的 DeepSeek 工具只认某个固定文件名（例如 `AGENTS.md`、`.cursorrules`），`AGENTS.md` 已经备好；
> 也可以直接把 `CLAUDE.md` 复制一份成那个名字。

## 1. 交接包里有什么

```
cloudsea-v2/
├─ AGENTS.md            ← 入口：项目一句话 + 三条命令 + 五条禁令 + 改完必做
├─ CLAUDE.md            ← 完整 AI 操作手册（架构、不变量、流程、坑、待办、验收）
├─ README.md            ← 人看的：怎么跑、怎么玩、URL 参数
├─ docs/
│  ├─ 交接.md            ← 本文件
│  ├─ 开发日志.md        ← 按时间的方向性变更（M0 → M25），每节都有"为什么 / 怎么验证 / 数据"
│  ├─ 开发计划.md        ← 最早的 M0–M9 计划（历史参考）
│  └─ bench/m0..m9.md   ← 早期里程碑的实现与帧时数据
├─ src/                 ← 9 个 JS 模块 + 8 个着色器
├─ index.html
├─ tools/
│  ├─ build-singlefile.mjs   ← 单文件打包
│  ├─ bench-server.py        ← 帧时收集器
│  └─ verify.ps1             ← 一条命令自检
├─ assets/noise.png
├─ shots/               ← 各里程碑的截图与前后对比图
└─ dist/cloudsea.html   ← 已构建的发布包（双击可玩）
```

不含：`.git`（历史在 `docs/开发日志.md` 里）、`shots/verify/`、浏览器临时 profile、`*.log`。

运行环境：Windows + Edge（或 Chrome）、Node（只用来打包）、Python（只用来起本地 HTTP 服务）。没有 npm 依赖。

## 2. 第一句话怎么说

最省事的开场（把"验收标准"和"改完要自检"写进第一句话，否则它容易改完就交）：

> 先完整阅读 `AGENTS.md` 和 `CLAUDE.md`，再读 `docs/开发日志.md` 最后三节。
> 然后按 `CLAUDE.md` §8 待办从第 1 项（音频）开始做。每完成一项：`node --check` 改过的 JS、
> 跑 `powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify.ps1`、用 `file://` 打开 `dist/cloudsea.html` 实测一次、
> 量 1080p 帧时，最后把改动、原因、验证结果写进 `docs/开发日志.md`。

只想让它先熟悉项目：

> 读 `AGENTS.md`、`CLAUDE.md` 和 `docs/开发日志.md`，用 200 字总结渲染结构（7 个 pass、哪些 pass 有编译变体）、
> 列车状态机和当前最该做的事。不要改任何代码。

## 3. 明确告诉它不能做什么

都写进 `CLAUDE.md` / `AGENTS.md` 了，但第一句话再强调一次更稳：

- 不要改变 `classic + 晴` 的画面（唯一回归基线）；
- 不要恢复乘客视角、大雨 / 大雪天气、神龙 / 云海巨鲸，也不要重新引入诗词 / 工作台；
- 不要手改 `dist/`；
- 不要用 PowerShell 批量改源码（会破坏 UTF-8 中文）；
- 1080p 超过 12 ms 先优化，不要偷偷砍功能；
- **大块的新效果代码要放进编译变体（`#ifdef`），不要只靠 `if (uniform)` 跳过**——本项目踩过三次：
  代码哪怕不执行，也会让 Intel 核显每帧多花 0.5–3.5 ms。

## 4. 它改完你怎么验收

1. **自检**：`powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify.ps1`
   - 构建单文件、起本地服务、渲染 6 张确定性截图（4 主题 + 晴 / 雷暴）、检查控制台；产物在 `shots/verify/`。
   - 注意：它测的是**开发页**。发布包要另外双击 `dist/cloudsea.html` 看一眼（见 §6 第一条坑）。
2. **看帧时**：启动 `python tools/bench-server.py`，打开
   `http://127.0.0.1:8789/index.html?bench=60&w=1920&h=1080&quality=1&theme=cyber&report=1`
   （测雷暴加 `&weather=storm`），结果追加到 `shots/bench.jsonl`。本机噪声约 ±1 ms，**要交替跑多次取中位数**再比较。
3. **看差异**：让它说明"改了哪些文件、为什么、怎么验证的"，并给出前后截图或逐像素对比数据；只说"已完成"不算。

## 6. 已知的坑（省它几个小时，全部踩过）

- **单文件构建会把所有模块拼进同一个作用域**：两个模块都有顶层 `const clamp01` 时，开发页正常、`dist` 直接
  `SyntaxError` 白屏，而 `verify.ps1` 测不出来。新模块的顶层名字加前缀；改完用 `file://` 开一次 `dist`。
- **不执行的着色器代码也要付钱**：大块效果放进 `#ifdef` 变体（现在 sky / composite / final 各有两个），渲染时按状态选 program。
- **`smoothstep(edge0 > edge1)` 是未定义行为**：硬切边、白斑、不同 GPU 表现不同；反向渐变写 `1.0 - smoothstep(a, b, x)`。
- **`?bench` 不走帧循环**：要测的状态（天气、闪电、演出）必须在 `runBench()` 里显式上传，否则量到的是晴天。
- **逐像素对比要固定 `?cloudscale=1`**：自动画质会按帧时改云倍率；新效果如果用随机数，冻结模式下要关掉。
- **大包围盒里的 8 倍频 fbm 很贵**：噪声项有界时，先判断像素是否可能命中再算（输出不变）。
- **`iChannel0` 复用**会让多 pass 的噪声采样错位，噪声必须走 `uNoise`；
- **风速**要独立维护 `cloudTime`，否则切天气时云会瞬移；
- **帧时**用 `readPixels` 同步，`gl.finish()` 在部分后端量不到；
- **PowerShell 5.1 的 `Compress-Archive`** 会把中文文件名打坏（本包用 Python `zipfile` 生成）。

## 7. 一个提醒

这个项目的复杂度集中在**着色器与 pass 编排**，不在业务逻辑。给任务时描述"视觉目标 + 可测量的验收"，
而不是"你看着办"。例如不要写"让雷暴更压抑"，写"雷暴时云层平均高度下降 10% 画面高、亮度再降 15%，
晴天逐像素不变，1080p 帧时增加不超过 1 ms"。有参考图就一起给——这个项目里所有效果第一版都在对着参考图返工。
