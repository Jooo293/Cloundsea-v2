# 交接给 Claude（或其他 AI 编码助手）

> 目标：把项目交出去之后，对方能在**不问你**的情况下跑起来、改对地方、并且知道什么不能碰。

## 0. 先选交付方式

| 方式 | 适合 | 怎么做 |
| --- | --- | --- |
| **Claude Code（推荐）** | 可以反复迭代、能跑命令 | 把整个文件夹交给它，它会自动读根目录的 `CLAUDE.md` |
| Claude 网页版 / 项目 | 只改局部、或先做方案 | 上传 zip（含 `CLAUDE.md` + `README.md` + `docs/`），先让它给方案再贴代码 |
| API / Agent 平台 | 接自动化流程 | 把 `CLAUDE.md` 作为 system prompt 的一部分，仓库挂成工具 |

无论哪种，**先让它在全新会话里读 `CLAUDE.md`**，不要在你现在这个长会话里继续——上下文里塞了十几轮迭代细节，反而会干扰它。

## 1. 交付包里必须有的东西

```
cloudsea-v2/
├─ CLAUDE.md            ← AI 操作手册（不变量、流程、坑、验收）
├─ README.md            ← 人看的：怎么跑、怎么打包、功能一览
├─ docs/
│  ├─ 开发日志.md        ← 按时间的方向性变更
│  ├─ 开发计划.md        ← 最早的 M0–M9 计划（历史参考）
│  └─ bench/m0..m9.md   ← 每个里程碑的实现与帧时数据
├─ src/                 ← 8 个模块 + 8 个着色器
├─ index.html
├─ tools/
│  ├─ build-singlefile.mjs
│  ├─ bench-server.py
│  └─ verify.ps1        ← 一条命令自检
├─ assets/noise.png
└─ dist/cloudsea.html   ← 已构建的发布包（可选，但建议带上）
```

**不需要带**：`shots/verify/`、`.edge-profile*`、`*.log`（`.gitignore` 已排除）。

打包：在 `cloudsea-v2` 的上一级执行

```powershell
Compress-Archive -Path cloudsea-v2 -DestinationPath cloudsea-v2.zip -Force
```

## 2. 第一句话怎么说

最省事的开场：

> 读 `CLAUDE.md`，然后按 §8 的待办从第 1 项（音频）开始做。每完成一项，跑 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/verify.ps1`，把结果和改动写进 `docs/开发日志.md`。

如果只想让它先熟悉项目：

> 读 `CLAUDE.md` 和 `docs/开发日志.md`，用 200 字总结这个项目的渲染结构、状态机和当前最该修的问题，不要改任何代码。

要点：**把"验收标准"和"改完要自检"写进第一句话**，否则它容易改完就交。

## 3. 明确告诉它不能做什么

这些写进 `CLAUDE.md` 了，但第一句话再强调一次更稳：

- 不要动 `classic + 晴` 的画面（那是唯一回归基线）；
- 不要恢复乘客视角，也不要重新引入诗词/工作台；
- 不要手改 `dist/`，改完源码重新构建；
- 不要用 PowerShell 批量改源码（会破坏 UTF-8 中文）；
- 1080p 超过 12 ms 就先降云倍率，不要偷偷砍功能。

## 4. 它改完你怎么验收

1. **自检**：`powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify.ps1`
   - 会构建单文件、起本地服务、渲染 8 张确定性截图（4 主题 + 4 天气）、检查控制台；
   - 产物在 `shots/verify/`，失败会打印哪一张、什么错误。
2. **看帧时**：启动 `python tools/bench-server.py`，打开
   `http://127.0.0.1:8789/index.html?bench=60&w=1920&h=1080&quality=1&theme=cyber&report=1`
   结果追加到 `shots/bench.jsonl`，和 `docs/bench/` 里的历史值对比。
3. **看差异**：让它说明"改了哪些文件、为什么、怎么验证的"。如果它只说"已完成"，让它给出截图或数据。

## 5. 建议的任务顺序（写进第一句话也行）

| 顺序 | 任务 | 验收 |
| --- | --- | --- |
| 1 | 音频：风声随天气、雷声跟闪电、起飞音效（WebAudio 合成） | 四种天气音量/音色不同；静音开关可用 |
| 2 | 龙卷把云吹散：中心附近下压云高 + 向外甩的弧线 | 雷暴下云层出现明显缺口，帧时增幅 < 1.5 ms |
| 3 | 竖屏构图：430×860 下不挤压 | 手机截图里列车与云层比例合理 |
| 4 | 飞行姿态：抬轮/倾斜 + 轮廓光 + 尾迹 | 飞行截图能看出"在飞"而不是"一道光" |
| 5 | 雷暴云增厚、废墟墨线重做、极光混色 | 对应截图与概念图对照 |

## 6. 已知的坑（省它几个小时）

- **`iChannel0` 复用**会让多 pass 的噪声采样错位（烟雾变香蕉形），噪声必须走 `uNoise`；
- **桥淡出**写成 `1-(1-k)*fade` 无效，正确是 `mix(col, bridge, (1-k)*fade)`；
- **风速**要独立维护 `cloudTime`，否则切天气云会瞬移；
- **`hidden` 属性**和 `.show` 类要一起切；
- **帧时**用 `readPixels` 同步，`gl.finish()` 在部分后端量不到；
- **PowerShell 的 `Set-Content`/`Add-Content`** 会把中文写坏——用编辑器或 Python 读写。

## 7. 一个提醒

这个项目的复杂度集中在**着色器与 pass 编排**，不在业务逻辑。给它任务时，尽量描述"视觉目标 + 可测量的验收"，而不是"你看着办"——例如不要写"让龙卷更明显"，写"雷暴时云层在龙卷中心出现直径约 15% 画面宽的缺口，帧时增加不超过 1.5 ms"。
